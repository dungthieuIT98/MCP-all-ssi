auth-proxy

OAuth 2.1 reverse proxy — gateway duy nhất cho cả hai downstream (mcp-trino và mcp-superset). Xác thực người dùng qua Azure AD OIDC (device code flow), cache token, tự động refresh, rồi inject Bearer token vào mọi request trước khi forward.

:6275 (listen):6274 → mcp-trino:fastmcp → mcp-superset
Azure AD OIDC flow:
1. Client gửi request đến :6275/mcp
2. auth-proxy redirect → Azure AD device code
3. User xác nhận trên thiết bị
4. Azure AD trả về access_token (JWT)
5. Token cache tại /app/cache/token_cache.json
6. Request được inject Authorization: Bearer <token> rồi forward

Security Architecture

Read-Only Enforcement

mcp-trino parses every SQL statement and blocks any non-SELECT operation before it reaches Trino.

OAuth 2.1 / Azure AD

auth-proxy implements device code flow. Tokens are cached and refreshed automatically; clients never handle credentials.

User Impersonation

mcp-trino forwards the authenticated user identity to Trino so row-level security and audit logs reflect the real caller.

Allowlisting

Catalog, schema, and table allowlists in mcp-trino configuration restrict which data assets are visible to MCP clients.

Network Isolation

All Docker services run on the internal trino-net bridge. Only mapped ports are exposed to the host.

Token Injection

auth-proxy strips client-provided auth headers and injects fresh Azure AD Bearer tokens before forwarding, preventing token spoofing.

Auth Proxy — Azure AD OIDC Flow

Azure AD OIDC (device code flow)
Token acquired & injected
MCP request/response
User action (out-of-band)
Token lifecycle: Token hết hạn → token_valid() = false → tự động gọi refresh_token() với grant_type=refresh_token. Nếu refresh fail (invalid_grant / interaction_required) → xóa token → restart device code flow. JWT payload được decode (base64) để lấy upn/email/preferred_username → dùng cho Trino user impersonation.

Superset → Trino Query Flow

Superset → Trino connection: Superset kết nối Trino qua Trino SQLAlchemy connector (configured trong Superset Database settings). Khi AI gọi superset_sqllab_execute_query, Superset nhận SQL → chạy qua connector → gửi đến Trino engine. Flow này không đi qua mcp-trino (Go server) — Superset tự kết nối trực tiếp đến Trino port :8080. mcp-trino chỉ được dùng khi AI client gọi trực tiếp tool execute_query của MCP.
